## Design Context

### Surface type
Databricks App — AppKit (Express server + React/Vite client, `@databricks/appkit-ui`).

### Audience
Field demo to customers — an SA presents it live to insurance prospects as a reference underwriting app.

### Theme
Both — light default, dark via toggle (persisted, respects `prefers-color-scheme` on first load).

### Use case
An underwriter reviews West-region renewals ranked by predicted claim risk, inspects the driving evidence, consults the governed copilot, and records a human approve/override decision in Lakebase.

### Brand (locked)
- Palette: Lava 600 #FF3621 (10% accent), Navy 900 #0B2026, Light #F9F7F4
- Typography: DM Sans 400/500/700 + DM Mono
- Components: Du Bois first (in this app: `@databricks/appkit-ui` primitives)
- Voice: Databricks editorial-plain (no superlatives, plain statements)

### Additional constraints
- Must work at 375 px (full responsive pass, 44 × 44 px touch targets).
- WCAG AA in both themes.
- Projector-legible: body ≥ 16 px, no low-contrast muted text on the dominant screen.

## Design Brief

### User journey
An underwriter picks the riskiest upcoming renewal from the queue, reviews its evidence and copilot recommendation, and records a decision.

1. Land on **Review queue** — see what needs attention (count, loss at risk, renewals in 30 days) and the ranked list.
2. Select a policy row → open **Policy review** for that policy (`/policies/:policyId`).
3. Read the evidence panel (risk probability, band, 90-day driving events, prior claims, premium).
4. Ask the copilot (prefilled prompt, one click) → read the recommendation.
5. Choose an action, add a note, and **Approve** or **Override** → confirmation, the decision appears in the policy's history inline; "Next policy" returns to the queue's next row.

Secondary surfaces: **Ask Genie** (exploratory portfolio questions) and **Decisions** (cross-portfolio audit log).

### Screens
1. **Review queue** (`/`) — triage. Primary action: open a policy.
2. **Policy review** (`/policies/:policyId`) — dominant screen. Primary action: record decision.
3. **Ask Genie** (`/genie`) — free-form governed Q&A. Primary action: ask a question.
4. **Decisions** (`/decisions`) — audit log, filterable by decision type. Primary action: open the related policy.

### Component inventory

**Du Bois / AppKit UI** (use as-is):
- `Sidebar` + `SidebarProvider` / `SidebarTrigger`: app shell nav (collapses to a sheet on mobile) — replaces the current top-bar tabs.
- `Breadcrumb`: Review queue › POL-000004 on the policy screen.
- `DataTable` / `Table`: review queue and decisions log (sortable, row click → policy).
- `Badge`: risk band, decision status.
- `BarChart`: risk distribution (chart palette from tokens, not Lava).
- `Tabs`: Policy review mobile layout (Evidence / Copilot / Decision).
- `Textarea`, `Button`, `Spinner`: copilot prompt and run.
- `RadioGroup` + `Field*`: intervention action selection (4 options, all visible — replaces raw `<select>`).
- `AlertDialog`: confirm override (records a deviation from the recommendation).
- `Alert`: AI-generated disclaimer, request errors.
- `Empty`: empty queue, no decisions, no answer yet.
- `Skeleton`: loading for KPIs, tables, evidence.
- `Toaster`: decision recorded confirmation.
- `Tooltip`: risk-band thresholds, column definitions.
- `ToggleGroup`: decisions filter (All / Approved / Overridden), theme toggle.
- `GenieChat`: Ask Genie surface.
- `Item*`: evidence factor rows and guardrail list.

**Custom** (build, matching Du Bois patterns):
- `KpiStrip`: three inline figures in one bordered row (not three cards) — avoids the hero-metric card template; AppKit has no stat primitive.
- `RiskMeter`: horizontal bar showing probability against the 0.39 / 0.42 / 0.45 band thresholds — no threshold-scale primitive exists; communicates *why* the policy is flagged.
- `EvidenceFactorList`: driving-event counts with a portfolio-relative comparison (e.g. "3× West median") — composition of `Item` + DM Mono numerals; custom only in layout.
- `CopilotAnswer`: existing lightweight markdown renderer, restyled to tokens; AppKit doesn't ship a markdown block.
- `DecisionPanel`: composed form (RadioGroup + Textarea + Approve/Override) with recommendation pre-selected and "Recommended" label on that option.
- `ThemeToggle`: `ToggleGroup` wired to `next-themes` (`.dark`/`.light` class, persisted, system default).
- `BandDistribution`: replaces `BarChart` for risk distribution — four fixed bands that must share colors with `RiskBadge`/`RiskMeter`; ECharts can't read the theme-dependent band tokens.

### Build notes (first cut)

### Content hierarchy

- **Primary**: policy ID + risk probability/band (`RiskMeter`), and the decision panel.
- **Secondary**: driving evidence factors, copilot recommendation text.
- **Tertiary**: premium, renewal date, model alias, scored-at timestamp, masked customer name, governance footnote, prior decisions for this policy.

Review queue:
- **Primary**: ranked queue table (policy, renewal date, band, probability, top factor).
- **Secondary**: KPI strip, risk distribution chart.

### Interaction states to build
- **Queue table**: loading (skeleton rows), empty (`Empty`: "No West renewals above the review threshold"), error (`Alert` + retry), hover/focus/active row, selected row returning from policy.
- **KPI strip**: loading skeleton, error inline, stale-data note when `data_freshness` > 24 h.
- **Evidence panel**: loading, policy-not-found (`Empty` + back to queue), error.
- **Copilot**: idle (prefilled prompt), disabled until evidence loads, loading (`Spinner` + elapsed-time note at 10 s), success, timeout (90 s), error.
- **Decision panel**: default (rule recommendation preselected), copilot agrees / copilot differs / no copilot answer yet, Override disabled until note entered, submitting (button busy), success (toast + history row appears), validation error (note required), server error.
- **Decisions log**: loading, empty, error, filter active.
- **Genie**: inherits `GenieChat` states; wrap with disclaimer.
- **Theme toggle**: light/dark, persisted.
- Focus-visible rings on every interactive element; keyboard: `j/k` row nav and `Enter` open in queue (shown with `Kbd`).

### Responsive behavior
- **Mobile (≤ 768 px)**: sidebar → sheet via `SidebarTrigger`. Queue table → stacked list items (policy, band badge, probability, renewal). KPI strip stacks vertically. Policy review header stays; body becomes `Tabs` (Evidence / Copilot / Decision) with the Approve button sticky at the bottom of the Decision tab.
- **Tablet (768-1024 px)**: collapsed icon sidebar. Queue table keeps policy/band/probability/renewal, drops evidence column. Policy review single column: header → evidence → copilot → decision.
- **Desktop (≥ 1024 px)**: full sidebar, two-column policy review (evidence+copilot left, decision sticky right at ~22rem). Queue: table 2/3 + chart 1/3, KPI strip full width above.

### Data & API notes
- Existing queries cover everything: `review_queue`, `portfolio_summary`, `risk_distribution`, `policy_detail`; decisions via `GET /api/decisions?policyId=`.
- Portfolio-median comparisons ("3.1× med") need a small new query (`west_feature_medians.sql`) — optional; omit the comparison if we keep SQL unchanged.
- **Recommendation model (option C — rule + copilot):**
  - *Rule recommendation* is the system of record: returned per policy by `review_queue` and `policy_detail` as `recommended_action`, sent as `recommendedAction` on every decision, and preselected in `DecisionPanel` with a "Recommended" label. Replaces the hardcoded `SAFE_DRIVING_COACHING` (`AgentChat.tsx:68`, `:95`).
  - *Copilot* explains the rule recommendation and ends its answer with a machine-readable line `COPILOT_ACTION: <code>`. The server parses it, strips it from the displayed text, validates it against the action vocabulary, and returns `{ text, copilotAction }`. Agent instructions in `src/agents/underwriting_copilot.json` get the output contract.
  - *Agreement state* in the decision panel: "Copilot agrees" (neutral) or "Copilot suggests <action> instead" (`Alert`, non-destructive) with its one-line reason. Missing/invalid `COPILOT_ACTION` → no agreement line, rule recommendation unchanged.
  - *Audit*: decision body adds `copilotAction` (nullable); stored in `audit_events.event_payload` (no schema change to `underwriting_decisions`). Override = selected action ≠ rule recommendation; note required.
  - *Action vocabulary* (one list for app, copilot, Lakebase): `NO_ACTION`, `SAFE_DRIVING_COACHING`, `DEDUCTIBLE_REVIEW`, `HUMAN_RENEWAL_REVIEW` — matches the copilot's approved options.
  - *Open — rule source*: the pipeline's `recommended_intervention` is keyed on `behavior_risk_score` (bands 0.3/0.5/0.7, codes `MONITOR`/`SAFE_DRIVING_CHALLENGE`/`UNDERWRITER_REVIEW`), while the app ranks and bands on the ML `claim_risk_probability` (0.39/0.42/0.45). Using the pipeline value as-is can show "High" risk next to a `MONITOR` recommendation. Proposed default: derive the rule in the app queries from the displayed band — Critical → `HUMAN_RENEWAL_REVIEW`, High → `SAFE_DRIVING_COACHING`, Moderate → `SAFE_DRIVING_COACHING`, Low → `NO_ACTION`; `DEDUCTIBLE_REVIEW` is underwriter-selectable only. Pending user confirmation.

### Out of scope
- Bulk decisions across multiple policies.
- Multi-region switching (app is West-scoped by query and ABAC).
- Multi-turn copilot conversation threads (single question/answer per policy in this cut).
- Editing or reverting a recorded decision.
- Changing model, ABAC, or pipeline behavior.
